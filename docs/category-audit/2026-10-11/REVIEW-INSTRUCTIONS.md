# Game category review

Scope: 167 games in roster.json from production repository main a4b007f. Review assigned games only; do not add/remove games, change artwork, titles, URLs, sandbox, or site source. Owner authorizes corrections, push, deployment, maximum three categories per game.

Existing browse categories: Action, Simulators (catalog alias Simulation), Survival, Strategy, Multiplayer, Puzzle, Arcade, Adventure, Racing, Sports, Tower Defense. All and Update are navigation filters, not game categories. Existing catalog also has Casual. Prefer existing categories. Propose a new category only if core mechanics cannot be described accurately with existing ones (e.g. Platformer, Shooter, Rhythm, Educational); explain necessity. Do not add generic tags merely because a game has points, movement, a character, or a theme. Primary category is the main loop, then at most two other meaningful categories. Human multiplayer counts toward the three-category limit; online/local mode label is separate metadata.

Action: real-time combat or demanding action. Simulators: simulation of a real-world activity/system; no racing tag on free driving without races. Survival: enduring threats/resource pressure as core loop; lives alone insufficient. Strategy: planning/tactical/resource decisions. Puzzle: logic/manipulation solving. Arcade: short replayable score/timing/reflex loop. Adventure: exploration/narrative/progression central. Racing: compete on tracks/time courses. Sports: sport rules/activity. Tower Defense: deploy defenses to stop waves. Multiplayer: actual supported multiple HUMAN players, local or online. AI rivals and leaderboards are not multiplayer.

Play each accessible game in an isolated headless Playwright Chromium browser (Python playwright available). Keep one browser per worker, close it afterward. Use observed UI controls/keys; inspect screenshots and actual changes after input. Save durable screenshots/logs within worker-N/ and concise gameplay action/outcome evidence. Developer instructions/pages/first-party source may support modes and mechanics. Search dated local scout reports and thumbnail research for source URLs, but label prior evidence separately. A successful load, title, screenshot alone, script variables, or automated click without observed response is NOT gameplay verification. No login/signup, account changes, payments, multiplayer chat, posting, or shared user browser.

For blocked games, retry once with a reasonable loading allowance, consult first-party documentation plus prior gameplay receipts, flag current gameplay unverified. Do not guess tags or claim gameplay. Preserve current category if corrections are unsupported; propose document-backed corrections separately for supervisor review. Never adjudicate excluded games into publication; owner-decisions.json applies.

Output worker-N/review.json: array with slug,title,url,currentCategory,categories (ordered max 3), status (gameplay_verified|documented_only|unresolved), confidence (high|medium|low), mechanics, gameplay {attempted,actions,outcome,screenshotPaths,limitations}, sources [{url or repo relative path,kind,current or prior,detail}], multiplayerMode (Online multiplayer|Local 2-player|Local multiplayer|null), rationale, proposedNewCategories. Cover every assigned slug. Also worker-N/summary.md. Preserve historical evidence. You are not alone in this codebase; never revert others' changes. Own ONLY your worker-N output directory and optional worker-N helper script. Do not spawn more agents. Report progress and limitations to parent.
